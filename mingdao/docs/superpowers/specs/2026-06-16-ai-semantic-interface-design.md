# 明道语言 AI 语义接口设计文档

**日期**：2026-06-16
**状态**：设计完成
**目标**：为明道语言设计语义层 AI 接口，实现中文自然语言编程

---

## 一、目标与背景

明道语言目前没有任何 AI 集成，但作为中文编程语言天然适合中文 AI 交互。参考 MoonBit 的"AI 原生语言设计"理念——让语言和工具链对 AI 友好，使 AI 能依赖语义和工具反馈推理而非单纯依赖记忆——为明道设计一套语义查询协议，使任何大模型都能理解明道代码的结构化语义信息。

### 核心价值

- **中文自然语言编程**：用户用中文描述需求，AI 生成明道代码
- **语义层 AI 接口**：AI 能主动查询明道代码的符号、类型、作用域等结构化信息
- **验证-重试闭环**：AI 生成的代码经过语义验证，失败时自动重写

## 三、语义查询协议

### 3.1 协议格式

所有语义查询和响应均为 **JSON 格式**，便于大模型解析。

#### 查询格式

```json
{
  "查询类型": "列出符号 | 推断类型 | 查找作用域 | 获取关键字 | 获取标准库 | 验证代码",
  "参数": { ... }
}
```

#### 响应格式

```json
{
  "状态": "成功 | 失败",
  "结果": [ ... ],
  "错误信息": "..."
}
```

### 3.2 六大查询接口

| 查询类型 | 用途 | 参数 |
|---------|------|------|
| `列出符号` | 获取代码中所有符号（变量、函数、类型） | `代码` |
| `推断类型` | 获取表达式的推断类型 | `代码`, `上下文` |
| `查找作用域` | 获取变量的作用域链 | `变量名`, `代码` |
| `获取关键字` | 获取双字关键字表 | `分类`（可选） |
| `获取标准库` | 获取标准库模块和函数签名 | `模块`（可选） |
| `验证代码` | 验证代码片段通过解析和类型检查 | `代码` |

### 3.3 查询示例

#### 列出符号

查询：
```json
{
  "查询类型": "列出符号",
  "代码": "定义 求和 就是函 a, b：\n  返回 a 加 b"
}
```

响应：
```json
{
  "状态": "成功",
  "结果": [
    { "名称": "求和", "种类": "函数", "类型": "(整数, 整数) -> 整数", "行号": 1 },
    { "名称": "a", "种类": "参数", "类型": "整数", "行号": 1 },
    { "名称": "b", "种类": "参数", "类型": "整数", "行号": 1 }
  ]
}
```

#### 获取关键字

查询：
```json
{
  "查询类型": "获取关键字",
  "分类": "流程控制"
}
```

响应：
```json
{
  "状态": "成功",
  "结果": [
    { "关键字": "如果", "语义": "条件分支开始", "示例": "如果 x 大于 0 那么：" },
    { "关键字": "那么", "语义": "条件分支动作", "示例": "..." },
    { "关键字": "否则", "语义": "条件分支默认动作", "示例": "..." },
    { "关键字": "跳出", "语义": "跳出循环", "示例": "跳出" }
  ]
}
```

#### 验证代码

查询：
```json
{
  "查询类型": "验证代码",
  "代码": "定义 计算 就是函 x：\n  如果 x 大于 0 那么：\n    返回 x 加 1\n  否则：\n    返回 x 减 1"
}
```

响应：
```json
{
  "状态": "成功",
  "结果": {
    "解析通过": true,
    "类型检查": true,
    "警告": [],
    "推断类型": "(整数) -> 整数"
  }
}
```

## 四、AI 交互流程

### 4.1 完整交互流程

```
用户（中文需求）
     │
     ▼
┌─────────────────────────────────────────────────────────────┐
│  AI 适配层（adapter.rkt）                                    │
│                                                              │
│  1. 接收用户需求："写一个冒泡排序"                              │
│  2. 构造提示词（语法规范 + 标准库 + 用户需求）                   │
│  3. 调用大模型 API                                            │
│  4. 解析模型返回的明道代码                                     │
│  5. 调用语义验证接口验证代码                                    │
│  6. 如果验证失败，发送错误信息给模型重新生成（最多3次）           │
│  7. 返回最终代码给用户                                         │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 提示词构造策略

提示词由三部分组成：

#### Part 1：静态语法规范（不变，随每次请求发送）

```
你是明道语言的代码生成助手。明道语言特性：

【关键字】双字关键字，示例：定义、如果、那么、否则、对于、跳出、返回
【函数定义】定义 函数名 就是函 参数：
【变量定义】定义 变量名 就是 表达式
【函数调用】参数1, 参数2, 函数名
【条件分支】如果 条件 那么：
            语句
          否则：
            语句
【循环】对于 i 从 0 到 n：
【算术运算】加、减、乘、除、模、幂
【比较运算】等于、不等、大于、小于、大于等于、小于等于
```

#### Part 2：上下文信息（动态查询补充）

```
【可用标准库函数】
  - 列表操作：列表、索引、长度、列表修改、追加
  - 字符串：消息拼接、长度、子字符串
  - 文件：读文件、写文件
  - JSON：解析json、生成json
  - ...
```

#### Part 3：用户需求

```
【需求】写一个冒泡排序函数，输入一个整数列表，返回排序后的列表
【约束】使用明道语法，不要使用任何英文
```

### 4.3 验证-重试机制

```
生成代码
     │
     ▼
┌──────────────┐
│ 语义验证接口  │ ──通过──→ 返回代码给用户
└──────┬───────┘
       │失败
       ▼
  错误信息 + 上下文
       │
       ▼
   重新生成（最多3次）
       │
       ▼
   超过3次 → 返回错误，提示用户手动调整
```

### 4.4 会话上下文管理

```
【会话1】
用户：写一个计算阶乘的函数
AI：生成 factorial 函数

【会话2】（上下文保持）
用户：再加一个计算斐波那契的函数
AI：基于前一个函数的上下文，生成 fibonacci 函数

【会话3】
用户：帮我用这两个函数写一个测试
AI：理解 factorial 和 fibonacci 的签名，生成测试代码
```

```racket
 *ai-model*

;; 生成代码
(define (ai生成代码 用户需求 #:<keyword>会话 会话-id #:<keyword>provider #f #:<keyword>model #f)
  ;; 参数：
  ;;   用户需求 - 字符串，中文描述
  ;;   会话 - 会话 ID（用于保持上下文）
  ;;   provider - AI 提供商（如 "deepseek", "glm"）
  ;;   model - 模型名称（如 "deepseek-coder"）
  ;; 返回：生成的明道代码字符串
  ...)

;; 查询语义信息
(define (ai查询语义 查询-jso)
  ;; 参数：JSON 格式查询
  ;; 返回：JSON 格式结果
  ...)

;; 验证代码
(define (ai验证代码 代码)
  ;; 参数：明道代码字符串
  ;; 返回：验证结果（是否通过 + 错误信息）
  ...)
```

### 6.2 语义查询协议

文件：`mingdao/tools/ai/semantic-protocol.rkt`

```racket
#lang racket/base

(provide
 语义查询
 列出符号
 推断类型
 查找作用域
 获取关键字
 获取标准库)

;; 语义查询入口
(define (语义查询 查询-jso)
  (match (hash-ref 查询-jso '查询类型)
    ["列出符号" (列出符号 (hash-ref 查询-jso '代码))]
    ["推断类型" (推断类型 (hash-ref 查询-jso '代码) (hash-ref 查询-jso '上下文))]
    ["查找作用域" (查找作用域 (hash-ref 查询-jso '变量名) (hash-ref 查询-jso '代码))]
    ["获取关键字" (获取关键字 (hash-ref 查询-jso '分类))]
    ["获取标准库" (获取标准库 (hash-ref 查询-jso '模块))]
    [_ (raise "未知的查询类型")]))
```

### 6.3 提示词构造器

文件：`mingdao/tools/ai/prompt-builder.rkt`

```racket
#lang racket/base

(provide
 构造提示词
 构造系统提示词
 构造用户提示词)

;; 构造完整提示词
(define (构造提示词 用户需求 #:<keyword>上下文)
  (string-append
   (构造系统提示词)
   "\n\n"
   (if 上下文
       (构造上下文提示词 上下文)
       "")
   "\n\n"
   (构造用户提示词 用户需求)))

;; 系统提示词（静态语法规范）
(define (构造系统提示词)
  (string-append
   "你是明道语言的代码生成助手。\n\n"
   (获取关键字文本)
   "\n"
   (获取语法规则文本)
   "\n"
   (获取标准库摘要文本)))
```

### 6.4 会话状态管理

文件：`mingdao/tools/ai/session.rkt`

```racket
#lang racket/base

(provide
 ai初始化会话
 ai关闭会话
 ai获取会话
 ai添加上下文)

;; 会话数据结构
(struct 会话 (id 模型提供者 消息历史 生成代码上下文) #:transparent)

;; 会话存储（内存中）
(define *会话表* (make-hash))

(define (ai初始化会话 #:<keyword>模型 "deepseek-coder")
  (define 会话-id (generate-uuid))
  (define 新会话 (会话 会话-id 模型 '() '()))
  (hash-set! *会话表* 会话-id 新会话)
  会话-id)
```

## 七、CLI 使用方式

```bash
# 初始化 AI 会话（默认使用 DeepSeek）
racket -S mingdao mingdao/tools/cli.rkt ai init

# 指定模型
racket -S mingdao mingdao/tools/cli.rkt ai init --provider glm --model glm-4

# 生成代码
racket -S mingdao mingdao/tools/cli.rkt ai generate "写一个冒泡排序"

# 在 REPL 中使用
racket mingdao/repl.rkt
> /ai 写一个计算阶乘的函数
```

# M6 — SSA IR 与优化 实现计划

实施日期：2026-06-16

## 总体目标

在 `lang/ir.rkt` 中实现 SSA IR，集成到 `lang/reader.rkt` 管道，提供经典优化。默认启用，可用开关禁用。

## 里程碑

### M6.1：IR 数据结构与工具函数

**文件：** `mingdao/lang/ir.rkt`（约 200 行）

**任务：**
1. 定义所有 struct（ir-value/ir-const/ir-var/ir-label）
2. 定义所有指令 struct（ir-instr/ir-assign/ir-load/ir-store/ir-binop/ir-unop/ir-cmp/ir-call/ir-phi/ir-ret/ir-br/ir-cond-br）
3. 定义 ir-block/ir-function/ir-module
4. 实现工具函数：
   - `(fresh-var [type])` → 产生 `%N` 名的 ir-var
   - `(fresh-label [prefix])` → 产生 `B-N` 名的 ir-label
   - `(make-block [label] [instrs] [terminator])` → 创建基本块
   - `(block->instr-list block)` → 展开 phi + 指令 + 终结符

**验证：** 写一个简单的 REPL 测试，构造一个函数并打印。

### M6.2：Lowering（AST → SSA IR）

**文件：** `mingdao/lang/ir.rkt`（约 350 行）

**任务：**
1. 定义 lowering 状态 `struct lower-state`（当前块、已完成块列表、var 计数器、label 计数器、可变变量表）
2. 实现 `lower-expr` 函数：匹配每种 AST 节点
3. 实现 `lower-if`：产生 then-block + else-block + merge-block + phi
4. 实现 `lower-for`：展开为 init/head/body/update/head 循环
5. 实现 `lower-function`：顶层函数定义 lowering
6. 实现 `lower-module`：遍历顶层表达式，组装 ir-module

**关键难点：** Phi 节点的正确插入。简化策略：
- if 的两个分支如果都修改了同一可变变量，在 merge 块放 phi
- for 的循环变量在 head 块用 phi 合并（初始值 + 更新值）

**验证：** 对示例代码 lowering → 打印 IR → 结构检查

### M6.3：优化 Passes（常量折叠 + DCE + CSE）

**文件：** `mingdao/lang/ir.rkt`（约 300 行）

**任务：**
1. **常量折叠**：遍历每个函数，对操作数都是 ir-const 的 ir-binop/ir-cmp/ir-unop 计算结果
2. **DCE**：从 ret/分支终点反向标记「活」指令，删除未被标记的
3. **CSE**：维护表达式哈希表（op, arg1-hash, arg2-hash）→ var，相同表达式复用

**验证：** 每个 pass 单独写测试用例 → 输入 IR 与预期输出 IR 比较

### M6.5：Emitting（IR → Racket）

**文件：** `mingdao/lang/ir.rkt`（约 300 行）

**任务：**
1. `(emit-instr instr)` → 单个指令的 Racket S-表达式
2. `(emit-block block)` → 块的 Racket S-表达式序列
3. `(emit-function fn)` → 函数翻译为 `(define (name params) body)`
4. `(emit-module m)` → 整个模块翻译为 `(begin def1 def2 ...)`

**控制流翻译策略（简化版）：**

由于 Racket 是高级语言，不需要真的用 goto/label。简化策略：

- **无 phi 的简单函数**：直接用 `let*` 串起所有指令
- **if**：翻译为 `(if cond then-expr else-expr)`，phi 直接变成条件表达式
- **for 循环**：翻译为 Racket 的 `for/list` 或普通 `do` 循环
- **递归/跳转**：用 `letrec` 绑定命名函数模拟块跳转

**实际做法（务实）：** 识别常见模式（if、for、顺序）直接翻译为对应的 Racket 结构；对识别不出来的复杂情况用「trampoline + 参数化闭包」或直接降级为普通 Racket。

**验证：**
- 对几个典型函数 emit → 手动检查输出
- 对 same program 跑两遍（IR 优化 vs 原始） → 输出一致

## 技术风险与应对

| 风险 | 影响 | 应对 |
|-----|------|------|
| Racket 的 struct 和 match 不支持复杂的 SSA 结构比较 | 测试编写困难 | 用 `equal?` 直接比较 struct（Racket struct 默认 transparent） |
| Phi 节点处理复杂，可能产生 bug | 优化后的代码可能逻辑错误 | 简化：初期只处理 if/for 的最常见 phi 情况，复杂情况直接跳过优化保留原始 IR |
| Emitting 处理不当，产生无效 Racket 代码 | 无法执行 | 写大量小单元测试；复杂 emit 降级为原始 AST |
| Lowering 遗漏某些 AST 模式 | 部分代码无法走 IR 路径 | 用 `match` 兜底分支，遇到不认识的 AST 直接降级为原始代码 |

# 明道语言语法问题分析报告

## 发现的关键问题

### 问题1：标识符读取不检查关键字边界 ⚠️⚠️⚠️

**现象**：
```
输入: x等于y
输出: (token 'IDENTIFIER "x等于y")  ❌
期望: x, 等于, y（三个token）
```

**原因**：`read-identifier` 函数（第147-165行）贪婪读取所有中文字符，不会在遇到关键字时停止。

**影响范围**：
- `分数大于等于90` → 被识别为一个标识符
- `a加b` → 被识别为一个标识符
- `定义x就是5` → 只有 `定义` 被识别，`x就是5` 成为一个标识符

**位置**：tokenizer.rkt 第147-165行

---

### 问题2：双字关键字匹配条件错误 ⚠️⚠️

**现象**：
```
输入: 定义定义x
输出: (token 'IDENTIFIER "定义定义x")  ❌
期望: 定义, 定义, x（三个token）
```

**原因**：第282-285行的双字关键字匹配条件是"下一个字符不是中文"，这导致当关键字后跟其他中文字符时无法匹配。

**代码片段**：
```racket
[(and (member potential-two-char 双字关键字)
      (not (and (peek 1) (中文? (peek 1)))))  ;; 这个条件有问题！
 (advance)
 (set! tokens (cons (token 'KEYWORD potential-two-char line (- col 1)) tokens))]
```

---

### 问题3：运算符识别逻辑错误 ⚠️⚠️

**现象**：
```
输入: a加b
输出: (token 'IDENTIFIER "a加b")  ❌
期望: a, 加, b（三个token）
```

**原因**：
1. 主循环处理中文时，运算符匹配在第292行
2. 但当第一个字符是英文时（如 `a`），会进入第344行的英文标识符分支
3. 英文标识符分支会贪婪读取所有中文（包括运算符）

**位置**：tokenizer.rkt 第292-295行，第344-358行

---

### 问题4：read-identifier 没有边界检查

**当前代码**（第147-165行）：
```racket
(define (read-identifier first-char)
  (define start-line line)
  (define start-col (sub1 col))
  (define chars (list first-char))
  (let loop ()
    (define ch (peek))
    (cond
      [(and ch (中文? ch))
       (set! chars (cons ch chars))
       (advance)
       (loop)]
      [(and ch (or (char-alphabetic? ch) ...))
       (set! chars (cons ch chars))
       (advance)
       (loop)]
      [else
       (token 'IDENTIFIER ...)])))
```

**问题**：没有检查读入的字符是否是关键字/运算符的开头。

## 修复方案

### 修复1：read-identifier 添加关键字边界检查

```racket
(define (read-identifier first-char)
  (define start-line line)
  (define start-col (sub1 col))
  (define chars (list first-char))
  
  ;; 辅助函数：检查字符是否可能是关键字/运算符的开头
  (define (could-start-keyword? ch)
    (and (char? ch)
         (ormap (λ (kw) (char=? (string-ref kw 0) ch))
                (append 双字关键字 三字关键字 四字关键字 单字关键字 单字运算符))))
  
  (let loop ()
    (define ch (peek))
    (cond
      ;; 【关键】如果下一个中文可能是关键字开头，立即停止
      [(and ch (中文? ch) (could-start-keyword? ch))
       (token 'IDENTIFIER (list->string (reverse chars)) start-line start-col)]
      ;; 普通中文字符，继续读入
      [(and ch (中文? ch))
       (set! chars (cons ch chars))
       (advance)
       (loop)]
      ;; 英文/数字/下划线
      [(and ch (or (char-alphabetic? ch) (char-numeric? ch) (char=? ch #\_) (char=? ch #\-)))
       (set! chars (cons ch chars))
       (advance)
       (loop)]
      [else
       (token 'IDENTIFIER (list->string (reverse chars)) start-line start-col)])))
```

### 修复2：双字关键字无条件匹配

删除"下一个字符不是中文"的条件：

```racket
;; 双字关键字（无条件匹配）
[(member potential-two-char 双字关键字)
 (advance)  ;; 消耗第二个字符
 (set! tokens (cons (token 'KEYWORD potential-two-char line (- col 1)) tokens))]
```

### 修复3：英文标识符分支也要检查关键字边界

```racket
;; 其他字符（英文标识符等）
[(or (char-alphabetic? ch) (char=? ch #\_))
 (advance)
 (define start-col col)
 (define chars (list ch))
 
 (define (could-start-keyword? c)
   (and (char? c)
        (ormap (λ (kw) (char=? (string-ref kw 0) c))
               (append 双字关键字 三字关键字 四字关键字 单字关键字 单字运算符))))
 
 (let ident-loop ()
   (define next (peek))
   (cond
     ;; 【优先】中文且可能是关键字开头 → 停止
     [(and next (中文? next) (could-start-keyword? next))
      (void)]
     ;; 中文且不是关键字开头 → 继续读入
     [(and next (中文? next) (not (could-start-keyword? next)))
      (set! chars (cons next chars))
      (advance)
      (ident-loop)]
     ;; 英文/数字/下划线 → 继续读入
     [(and next (not (中文? next)) (or (char-alphabetic? next) (char-numeric? next) (char=? next #\_)))
      (set! chars (cons next chars))
      (advance)
      (ident-loop)]
     [else (void)]))
 (set! tokens (cons (token 'IDENTIFIER (list->string (reverse chars)) line start-col) tokens))
 (main-loop)]
```

## 其他发现的问题

### 问题5：复合标识符设计有问题

当前代码（第273-279行）硬编码了"复合标识符"：

```racket
(define 复合标识符
  '("列表修改" "消息拼接" "索引位置" "当前符号" "新状态"))
```

这种设计不灵活，用户无法创建类似命名。建议移除这个机制，改为让用户使用空格或下划线分隔。

### 问题6：运算符命名混淆

变量名 `单字运算符` 实际包含的是双字词（如 `"加" "减"`），命名容易误导。建议重命名为 `运算符关键字`。

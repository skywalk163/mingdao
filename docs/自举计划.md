# 明道自举（Bootstrapping）实现计划

> ✅ **已完成 Phase 1-3**：基础库扩充 → 明道版 Parser → 自举一致性验证（2026-06-01）
>
> 所有 15 个测试用例的 Token 流和 AST 在 Racket 版与明道版之间完全一致。

## 目标

用明道语言自身编写分词器（tokenizer）和解析器（parser），使其能编译自身源码。
第一阶段目标：明道写的 tokenizer + parser 生成 Racket S-表达式，仍依赖 Racket 运行时。
第二阶段目标（可选）：实现明道解释器，完全脱离 Racket。

```
└──────────────────┬──────────────────────────────────┘
                   │
                   ▼
┌─────────────────────────────────────────────────────┐
│               Tokenizer（明道自写）                    │
│  字符流 → Token 流                                    │
│  输出：((token 'KEYWORD "定义" 1 1) ...)              │
└──────────────────┬──────────────────────────────────┘

┌─────────────────────────────────────────────────────┐
│                Parser（明道自写）                      │

                   │
                   ▼
┌─────────────────────────────────────────────────────┐
│            Racket 运行时（eval AST）                   │
└─────────────────────────────────────────────────────┘
```

## 前提

自举需要明道具备字符级操作能力。以下是**必须先实现**的基础函数：

### 需要新增的内置函数（在 core.rkt 中）

| 明道函数 | 功能 | 映射到 Racket |
|---------|------|-------------|
| `字符` | 整数→字符 | `integer->char` |
| `字符码` | 字符→整数 | `char->integer` |
| `字符串索引` | 取字符串第n个字符 | `string-ref` |
| `子字符串` | 取子串 | `substring` |
| `字符串长度` | 字符串长度 | `string-length` |
| `字符串转列表` | 字符串→字符列表 | `string->list` |
| `列表转字符串` | 字符列表→字符串 | `list->string` |
| `是中文?` | 判断是否中文字符 | 自定义 Char-range 检查 |
| `是数字?` | 判断是否数字字符 | `char-numeric?` |
| `是字母?` | 判断是否字母字符 | `char-alphabetic?` |
| `是空白?` | 判断是否空白字符 | `char-whitespace?` |
| `是换行?` | 判断是否换行符 | 直接比较 |
| `字符串前缀?` | 检查前缀 | `string-prefix?` |
| `字符串包含?` | 检查子串 | `string-contains?` |
| `追加` | 列表追加元素 | `cons` |
| `反转` | 列表反转 | `reverse` |
| `数字转字符串` | 数字→字符串 | `number->string` |
| `字符串拼接` | 字符串拼接 | `string-append` |
| `报错` | 抛出错误 | `error` |
| `判断` | 条件分支（内置版） | `if` |
| `相等?` | 通用相等判断 | `equal?` |

这些函数总计约 50 行 `core.rkt` 代码，是后续所有自举工作的基础。

## 第二阶段：用明道写 Tokenizer

**工作量**：约 250 行明道代码
**工期估计**：3-5 天
**验证标准**：明道写的 tokenizer 对同一段源码输出与 Racket 版 tokenizer 相同的 Token 列表

### 2.1 关键字数据（明道版）

用 明道 的 `列表` 来存放关键字表：

```明道
定义控制流关键字就是列表,"定义","如果","那么","否则","对于","跳出","继续","返回","赋值"
定义双字关键字就是列表,"定义","如果","那么","否则","列表","索引","长度","打印",…
定义单字关键字就是列表,"从","到","为"
定义四字关键字就是列表,"大于等于","小于等于","对于每个"
定义三字关键字就是列表,"就是函","就是宏","否则若","当满足","定义宏"
定义单字运算符就是列表,"加","减","乘","除","模","幂","非","与","或"
```

### 2.2 Token 数据结构

用 明道 的 `字典` 或嵌套列表表示 Token：

```明道
定义创建Token就是函类型,值,行,列：
  定义空就是列表,"token",类型,值,行,列
  
# 或者用字典
定义创建Token就是函类型,值,行,列：
  定义空就是字典,类型,类型,值,值,行,行,列,列
```

### 2.3 核心函数

需要在明道中实现以下函数：

| 明道函数 | 功能 | 核心逻辑 |
|---------|------|---------|
| `分词` | 分词主入口 | 遍历字符列表，分发给各读取函数 |
| `是关键字?` | 检查关键字匹配 | 对关键字表做前缀匹配 |
| `读字符串` | 读取"…"字符串 | 找到闭合引号 |
| `读数字` | 读取 123/3.14 | 收集连续数字和点号 |
| `读标识符` | 读取中文标识符 | 收集连续中文+字符 |
| `看下一个` | 窥视（peek） | 索引字符列表 |
| `前进` | 前进一位 | 更新位置索引 |
| `跳过空白` | 跳过空格/tab | 递归跳过 |

### 2.4 Tokenizer 接口

```明道
定义分词就是函源码：
  定义字符列表就是字符串转列表,源码
  定义结果列表就是分词循环,字符列表,1,1,空值
  结果列表
```

### 2.5 验证方法

```racket
;; tests/test-bootstrap-tokenizer.rkt
(define 明道源码 "定义汉诺塔就是函n,源,目标,辅助：\n 如果n等于0那么：\n  返回")
;; 用 Racket 版 tokenize
(define racket-tokens (tokenize 明道源码))
;; 用明道版分词（通过 eval 执行明道代码）
(define 明道-tokens (eval '(分词 "定义汉诺塔就是函n,源,目标,辅助：\n 如果n等于0那么：\n  返回") ns))
;; 比较输出
(check-equal? racket-tokens 明道-tokens)
```

## 第三阶段：用明道写 Parser

**工作量**：约 450 行明道代码
**工期估计**：5-7 天
**验证标准**：明道写的 parser 对同一段 Token 流输出与 Racket 版 parser 相同的 AST

### 3.1 递归下降解析

明道自身支持递归函数，所以可以将 parser 的递归下降结构直接翻译。

关键解析函数对应表：

| Racket 版函数 | 明道版函数 | 说明 |
|-------------|-----------|------|
| `parse-program` | `解析程序` | 主入口 |
| `parse-statement` | `解析语句` | 分发到具体语句 |
| `parse-definition` | `解析定义` | 处理 定义…就是… |
| `parse-if` | `解析如果` | 处理 如果…那么…否则… |
| `parse-for-loop` | `解析对于` | 处理 对于…从…到… |
| `parse-comma-exprs` | `解析逗号表达式` | 逗号分隔的表达式 |
| `parse-condition` | `解析条件` | 条件表达式 + 比较符 |
| `parse-expression` | `解析表达式` | 运算符优先级 |
| `parse-additive-expression` | `解析加减` | 加/减/拼接 |
| `parse-atomic-expression` | `解析原子` | 数字/字符串/标识符 |

### 3.2 函数名注册表

```明道
定义函数名表就是列表,"打印","长度","索引","加","减","乘","除","列表","列表修改","消息拼接"
定义注册函数名就是函名称：
  定义函数名表就是追加,函数名表,名称

定义是函数名?就是函名称：
  定义index就是列表索引,函数名表,名称
  定义返回就是不等,index,空值
```

### 3.3 AST 输出

Parser 输出与当前 Racket 版一致的 S-表达式列表。因为 明道的 `列表` 直接映射到 Racket 的 `list`，所以输出的嵌套列表就是合法的 Racket 代码。

```明道
# 示例：解析 "1加2"
解析程序,分词,"1加2"
# → (list (list '+ 1 2))
# 等价于 '((+ 1 2))
```

### 3.4 验证方法

```racket
;; tests/test-bootstrap-parser.rkt
(define 源码 "定义汉诺塔就是函n,源,目标,辅助：\n 如果n等于0那么：\n  返回")
(define tokens (tokenize 源码))
(define racket-ast (parse tokens '("汉诺塔")))
(define 明道-tokens (eval `(分词 ,源码) ns))
(define 明道-ast (eval `(解析程序 ,明道-tokens) ns))
(check-equal? racket-ast 明道-ast)
```

## 第四阶段：Bootstrap 验证

**工作量**：约 30 行测试代码
**工期估计**：1 天
**验证标准**：自举版能正确解析自身源码，产生与 Racket 版一致的 AST

### 自举验证流程

```
1. 用 Racket 版 明道 执行明道写的 tokenizer + parser
   生成 self-hosted-tokenizer 的 AST
   
2. 用 step 1 产出的 AST 去 tokenize + parse → self-hosted-parser 的 AST

3. 对比 step 1 和 step 2 的 AST：
   - 如果一致 → 自举成功 ✓
   - 如果不一致 → 找差异调试
```

具体测试：

```racket
;; tests/test-bootstrap-self.rkt
(define 自举源码 (port->string (open-input-file "mingdao/lang/bootstrap-tokenizer.mingdao")))
(define tokens (tokenize 自举源码))
(define ast (parse tokens '("分词" "是关键字?" "读标识符" "读字符串")))
;; 确认 AST 是合法的 Racket S-表达式
(for ([expr ast])
  (unless (list? expr)
    (error "AST 格式错误")))
(printf "✓ 自举 Tokenizer 源码解析成功\n")
```

## 第五阶段（可选）：实现明道解释器

**工作量**：300-500 行明道代码
**工期估计**：1-2 周
**验证标准**：明道解释器能执行简单的明道程序，不再依赖 Racket `eval`

如果前四个阶段完成，明道的 tokenizer 和 parser 已用明道自身实现。此时可以进一步实现一个**明道解释器**，完全独立于 Racket：

### 解释器架构

```明道
定义解释执行就是函源码：
  定义tokens就是分词,源码
  定义ast就是解析程序,tokens
  定义eval-ast,ast,空字典    ;; 空环境

定义eval-ast就是函ast,环境：
  对于每个expr从ast：
    判断,expr,0,"是列表?"  ;; 检查是否为函数调用
     …
```

### 依赖关系

解释器依赖的明道特性均已在前四个阶段验证：
- 递归（函数调用自身）
- 条件分支（如果…那么…否则…）
- 列表操作（索引、长度、追加）
- 字典（变量环境）

## 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 明道递归深度限制 | 深度嵌套的 AST 可能栈溢出 | 用迭代代替递归，或加大栈空间 |
| 列表操作效率 | 大文件分词可能慢 | 先在 100 行内测试 |
| 关键字更新不同步 | 新增关键字时两边都要改 | 从 Racket 版自动生成关键字数据 |
| 字符编码问题 | 中文 Unicode 范围检查 | 复用 `中文?` 中已定义的 Unicode 范围 |
